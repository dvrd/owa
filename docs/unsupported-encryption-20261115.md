# Unsupported encrypted receive handling (OKAMI-425)

Incoming encrypted types outside pkmsg/msg/skmsg previously fell through to a nil-payload success: the message could acquire a durable processed marker and ordinary receipt/ACK without decryption. A full-child preflight now refuses unsupported or mixed content before deduplication, self filtering or any staged ratchet/state work. Known msmsg receives negative ACK495 (MissingMessageSecret), other unsupported/missing types490 (UnrecognizedStanzaType), from the exact pinned Baileys decoder constants. No successful delivery receipt, success marker, application message or automatic retry is produced. NACK write failures propagate without state mutation. Existing unencrypted-control handling and the two-pass distribution-before-group decoder remain unchanged.

The behavioral regression fails on the old runtime (all three new tests fail), including exact disk mutation and missing negative ACK. The fixed full package passes49 tests under AddressSanitizer and allocation tracking. Replay tests reopen durable state three times and exercise direct/group, missing/unknown/msmsg, mixed child order and write failures. A supported/control preflight admission test preserves both distribution orders. These are synthetic/local checks, not a live account result.
